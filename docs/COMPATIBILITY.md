# StillPoint 兼容性测试报告

> 版本 0.1.0 · 测试时间 2026-10-30 · 本报告只写**实际跑过**的结果，未测项明确标注为「未测」。

## 1. 测试环境

| 项目 | 取值 |
| --- | --- |
| 操作系统 | Microsoft Windows NT 10.0.22631.0（Windows 11 23H2） |
| 显示器 | 单显示器 `\\.\DISPLAY1`，物理分辨率 **2560×1440**，桌面缩放 **125%**（120 dpi，165 Hz） |
| 任务栏 | 底部，60 px（物理），工作区底边 1380 px |
| 运行库 | 系统仅装 .NET 6/7；应用以 .NET 8 自包含单文件发布，运行时自带 |
| 测试对象 | `dist\StillPoint\StillPoint.exe`（自包含，139 MB）与 Debug 构建，两者行为一致 |
| 显卡/驱动 | 未记录（与结论无关，浮层走桌面合成而非游戏渲染管线） |
| 游戏 | 本机未安装任何受支持的游戏，因此用自研的两个测试宿主代替（见 §2） |

> 为什么不用真游戏：手头没有可复现的测试目标，标称「实测通过某个游戏」会变成无法验证的承诺。测试宿主在「窗口样式 / 全屏方式」层面与真游戏等价：一个是普通的无边框全屏窗口（和绝大多数「无边框全屏」游戏的窗口形态完全相同），另一个是真正的 D3D11 独占全屏交换链。

## 2. 测试工具（`tools/`）

| 工具 | 作用 |
| --- | --- |
| `FakeGame` | WPF 无边框全屏窗口（2560×1440，覆盖整个显示器），带帧计数、`BUTTON A/B` 点击计数、`%TEMP%` 状态文件；`--windowed` 走 1280×720 居中窗口 |
| `ExclusiveGame` | D3D11 独占全屏（`SetFullscreenState(TRUE)`），动画色彩，`--seconds N` 自动退出 |
| `capture.ps1` | DPI 感知的整屏截图（2560×1440 物理像素） |
| `clicktest.ps1` | DPI 感知的 `SendInput` 真实点击，并打印点击前后的 `WindowFromPoint` / 前台窗口 |

## 3. 逐项结果

### 3.1 桌面显示（基准）

- 结果：**通过**。16 个点全部出现，4×4 网格完整。
- 实测坐标：`x = 448.7 / 1002.7 / 1556.7 / 2110.7`，`y = 110.7 / 516.7 / 922.7 / 1328.7`（物理像素）。
- 与参考画面（《使命召唤》同一张 2560×1440 截图，逐像素测得的 `448 / 1002 / 1556 / 2110 × 112 / 517 / 922 / 1330`）偏差 **≤1.3 px**。
- 点径：白点核心约 6×6 px（= 0.45% 屏高），与参考一致。

### 3.2 无边框全屏游戏

- 方法：启动 `FakeGame`（全屏矩形 `0,0,2560×1440`，与显示器矩形完全一致）→ 等 6 秒 → 截屏 → 用 `clicktest.ps1` 在 `(173,1312)`（BUTTON A 中心）注入 2 次真实点击 → 再截屏 → 读 `%TEMP%\stillpoint-fakegame.status.txt`。
- 结果：**通过**。
  - 截屏中 16 个点稳定显示在游戏画面之上（见 `docs/images/fullscreen-borderless.png`）。
  - `clicks_a` 由 `0` 变为 **2**，游戏自己的计数也从 `A clicks: 0` 变为 `A clicks: 2` —— 说明点击**穿透**浮层落到了游戏里。
  - `WindowFromPoint` 与「前台窗口」在点击前后都仍是 `FakeGame` 的窗口（`HwndWrapper[FakeGame;;…]`，标题长度 38），**焦点没有被抢走**。
- 结论：无边框全屏下浮层可见、可穿透、不干扰操作。

### 3.3 窗口化游戏

- 方法：`FakeGame --windowed`（1280×720，左上角 `640,360`）→ 截屏。
- 结果：**通过**。16 个点覆盖整个桌面，在游戏窗口之上正常显示（`docs/images/windowed.png`）。

### 3.4 独占全屏（重要限制）

- 方法：启动 `ExclusiveGame --seconds 30`，等 8 秒（状态文件确认 `set_fullscreen_success=True`、`reported_fullscreen=True`、`frames` 持续增长）→ 截屏。
- 结果：**未覆盖（符合预期，非缺陷）**。截屏里只有独占全屏程序的画面（橄榄绿背景 + 移动彩条），**没有任何 StillPoint 的点**（`docs/images/fullscreen-exclusive.png`）。
- 原因：独占全屏（Flip Exclusive）不让桌面窗口管理器参与合成，DWM 不再把普通窗口叠到呈现面上；除了注入 / 渲染 Hook 这类做法，普通置顶窗口都画不上去。StillPoint 明确不采用注入路线。
- 退出独占全屏程序 3 秒后再截屏：16 个点**自动重新出现**，不需要重启工具。
- 产品应对：设置窗口的「运行与兼容性」里内置了这条说明，直接建议用户改用「无边框全屏 / 窗口化全屏」，不做「已支持独占全屏」的虚假承诺。

### 3.6 设置持久化

- 方法：把浮层关掉（`Enabled=false` 写入 `%LOCALAPPDATA%\StillPoint\settings.json`）→ `Stop-Process -Force` 强杀 → 重新启动。
- 结果：**通过**。启动日志里只有 `Settings loaded from …`、`Global hotkey registered`、`Startup complete.`，**没有** `Overlay window created.` —— 说明关掉的状态被正确恢复，重启后浮层确实不出现。
- 反方向也验证过：重新打开开关后浮层立即创建并按参数定位。

### 3.7 退出

- 方法：点设置窗口底栏「退出 StillPoint」→ 等 3 秒 → 检查进程与顶层窗口 → 截屏。
- 结果：**通过**。进程结束；UI Automation 枚举顶层窗口时已没有任何 StillPoint 窗口（浮层窗口也已销毁）；截屏里 16 个点全部消失，桌面无残留透明窗口。日志顺序：`Overlay window closed.` → `Overlay window destroyed.` → `==== StillPoint exiting ====`。

### 3.8 托盘

- 结果：**通过**。图标（深色圆角方块 + 4×4 白点）出现在 Windows 11 托盘溢出区（`docs/images/tray.png`）。
- **双击图标重新打开设置窗口**：实测通过——先关闭设置窗口（只剩浮层），再展开溢出区双击 StillPoint 图标，设置窗口重新出现（UI Automation 再次枚举到 `StillPoint` 顶层窗口）。
- 右键菜单含「打开设置… / 隐藏点阵 / 退出 StillPoint」，其显示/隐藏文案随浮层状态更新。
- 说明：Windows 11 默认把新图标收进溢出区，需要用户拖到任务栏才会常驻显示。

### 3.8.1 关闭设置窗口后浮层继续

- 方法：点窗口右上角关闭 → 等 1.2 秒 → 截图 → 统计点数。
- 结果：**通过**。设置窗口消失（UI Automation 查不到窗口），浮层仍在：检测到 **16/16** 个点。

### 3.9 高 DPI

- 结果：**通过（仅 125%）**。窗口使用 DIP 尺寸、浮层用 `GetDpiForWindow` 换算后以物理像素 `SetWindowPos`，实测浮层矩形与显示器矩形完全重合（`GetWindowRect` 校验 `0,0,2560,1440`）。预览里的点阵与外层点阵使用同一套比例参数。

### 3.10 资源占用

在「推荐版」（`dist\StillPoint`，自包含未压缩单文件）上实测（设置窗口隐藏、只剩浮层，稳定运行 45 秒）：

| 指标 | 实测 |
| --- | --- |
| CPU | 45 秒内累计 0.047 s（≈0.1% 单核） |
| 工作集 / 私有内存 | 169–173 MB / 145 MB |
| 句柄 | 691 |

内存大头是 WPF 自身（渲染 + 字体 + 桌面合成表面），不是我们的逻辑；1.2 秒一次的「置顶校正」只做几次 `SetWindowPos`/`GetWindowRect`，不重绘、不截图、不轮询游戏。

### 3.15 焦点与置顶鲁棒性

- 方法：`analysis/focus_test.ps1`。启动后依次让记事本、浏览器（Chrome）、微信成为前台窗口，各截一张图；再按两次 Alt+Tab 切换。
- 结果：**通过**。全程 16/16 点持续可见；前台窗口始终是别的应用，从未被 StillPoint 抢走焦点；进程只暴露 2 个顶层窗口（`StillPoint` 设置窗口 + `StillPoint Overlay` 浮层），浮层不进入 Alt+Tab / 任务栏。
- 说明：浮层带 `WS_EX_NOACTIVATE`，即使鼠标停在浮层上也点不到它，点击直接落到下面的窗口（§3.2 已用注入点击验证）。

### 3.16 浅色 / 深色主题

- 实现：两份键完全相同的资源字典 `Styles/Theme.xaml`、`Styles/ThemeDark.xaml`（`analysis/check_keys.py` 校验：两边各 23 个键，差集为空）；界面全部用 `DynamicResource` 引用，切换时只替换合并字典，窗口不重建。
- 结果：**通过**。在「外观 → 界面」点「深色」，已打开的窗口原地整体变色（无需重启）；`settings.json` 写入 `DarkTheme=true`；杀掉进程重启后仍是深色；点回「浅色」恢复并写回 `DarkTheme=false`。
- 修掉的两个真实缺陷：① 深色字典漏了字体键，切换后 `DynamicResource` 解析成 null，抛 `Value cannot be null (Parameter 'fontFamily')` 崩溃；② 颜色写成 CSS 风格 `#FFFFFF14`，WPF 按 `#AARRGGBB` 解析成「近透明黄」，卡片出现亮黄描边——改成 `#14FFFFFF` 等正确顺序后修好（顺带让浅色主题的 6% 描边真正生效）。
- 截图：`docs/images/settings-dark.png`、`docs/images/settings-runtime-dark.png`。

### 3.17 长时间稳定性（5 分钟连续运行）

- 方法：`analysis/soak.ps1`。启动后关闭设置窗口（只留浮层），每 15 秒采样一次。
- 结果：**通过，无泄漏迹象**。

| 时间 | CPU 累计 | 工作集 | 私有内存 | 句柄 | 线程 |
| --- | --- | --- | --- | --- | --- |
| 15 s | 0.000 s | 160.9 MB | 134.2 MB | 746 | 26 |
| 60 s | 0.000 s | 161.4 MB | 134.2 MB | 738 | 21 |
| 120 s | 0.000 s | 161.6 MB | 134.4 MB | 739 | 20 |
| 180 s | 0.016 s | 157.7 MB | 130.9 MB | 753 | 23 |
| 240 s | 0.016 s | 157.9 MB | 131.0 MB | 750 | 20 |

## 4. 未测项（明确标注，避免误解）

- 真实商业游戏的窗口化 / 无边框全屏（本机没有可测游戏）。
- 100%、150%、200% 缩放，以及 1080p / 4K 分辨率。
- 多显示器（本机只有一台；代码结构支持指定显示器，但 UI 尚未暴露）。
- 混合 DPI（不同显示器不同缩放）。
- 游戏内的 Alt+Tab / 分辨率切换、HDR、可变刷新率（桌面上的 Alt+Tab 已测，见 §3.15）。
- 长时间（数小时）驻留的内存曲线（目前只做到 5 分钟，见 §3.17）。

上述任何一项如果出现问题，都属于「还没验证」而不是「已支持」。
